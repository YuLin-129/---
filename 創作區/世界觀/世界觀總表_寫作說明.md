# 世界觀總表：世界觀條目的完整資料格式與寫法
> 撰寫：claude-fable-5-1（effort medium）・2026-10-26

> **世界觀總表**是一個世界（或一個地區、一個時代）調查完之後寫成的完整檔案（JSON），和 `角色總表` 是同一個做法：**最大還原、不直接送模型**，要用時**導出**成四種東西——常駐的總覽、每個實體的公開條目、真相書、劇情推演的種子。
> 這份說明：第 1 節是怎麼決定要寫什麼、寫到多細；第 2 節是欄位；第 3 節是導出對照表與每條條目的樣子；第 4 節是關鍵字與設定；第 5 節是範例；第 6 節是檢查表。守則與研究依據在 `docs/30_世界觀條目研究與守則.md`（守則 W1～W20）。空白骨架在 `世界觀總表_模板.json`，完整範例在 `世界觀總表_巴斯庫拉.json`（峽谷城與無聲迴廊，內容取自 `魯迪×姬絲秀忒_開場.md`）。
> 要交給 AI 寫時，把這份說明、模板、巴斯庫拉的範例一起給它。

## 1. 先決定要寫什麼

### 1.1 哪些東西值得一條

問兩個問題（和角色分級同一個邏輯）：

| 問題 | 答「會」 | 答「不會」 |
|---|---|---|
| 這個東西**不在了**，故事會少一條線、或角色會做出不同的決定嗎？ | 寫成一個實體（一條公開條目） | 併進上一層實體的 `people`／`common`，或寫進總覽 |
| 玩家會**反覆回到**這裡、提到它、問它嗎？ | 寫成一個實體 | 寫一句就好 |

拿不準就**併進上一層**。往下寫少了，之後補得回來（子條目可以隨時從上層拆出來）；往上寫多了，每個都會在觸發時搶預算，而且寫手會拿多出來的設定硬演。

**不寫成實體的**：一次性的場景、只出現在一段劇情裡的房間、不會再提到的路人攤販——寫進上層地點的 `people` 或 `common`。
**一定要寫的**：角色會住、會回去的地方；會影響角色決定的規則（錢、法律、魔法的限制）；角色之間會談到的歷史與傳聞；有「真相」的東西。

### 1.2 寫到多細

- **只做「看起來做了全部」的最少量**（Sanderson、Writing Excuses）。先寫故事會碰到的面，其餘用「未定」留白、用「這裡沒有」排除。
- **一個實體的 `common` 3～8 句**。超過就拆子實體（城 → 旅店、公會、市場），不要寫成 20 句的長條目。
- **越奇怪的設定因果越清楚、越平常的一句就好**。「這裡的太陽是綠色的」要寫為什麼、造成什麼；「這裡有旅店」一句。
- **先定三個特徵，其餘從環境推**（Jemisin）：寫文化、寫城市時，先決定三個最不一樣的事（裂谷、魔石、無聲），地形、經濟、食物、治安照這三件推出來。

### 1.3 三層知識

每個實體的事實分三層，寫的時候就分好，導出時才知道送給誰：

| 層 | 欄位 | 誰知道 | 導出到 |
|---|---|---|---|
| **常識** | `common` 與各類型的必填欄位 | 這個世界裡的一般人 | 公開條目的主體 |
| **在地** | `local.facts`＋`local.known_by` | 名單：在地人、成員、學者、某個角色 | 併進公開條目末段「○○才知道：…」；名單很窄時另立一條 |
| **真相** | `secret.facts`＋`secret.clues`＋`secret.known_by` | 作者、寫手、劇情推演（可加知道的角色名） | **真相書**，NPC 節點拿不到 |

寫在地層時可以用世界內來源的口吻、帶「據說」「老人說」，而且要寫**是誰說的**；常識與真相只用直述句。某個 NPC 知道的真相（老杜真的下過第八層）寫進**他的**角色私密條目，不寫在世界的真相書——世界的真相書是給旁白的。

### 1.4 會變的不寫進條目

現況、目標、時鐘、誰握著什麼——寫進 `now`，導出給劇情推演，條目只寫不變的。檢驗：「三十回合之後這句還會是對的嗎？」不會的進 `now`。

## 2. 欄位

頂層順序固定：`meta`、`overview`、`entities[]`、`review_checks[]`。不適用的欄位整個刪掉，**不留 null、不留空字串、不留空陣列**。所有文字繁體中文、台灣用語。

### 2.1 `meta`

| 欄位 | 寫什麼 |
|---|---|
| `world` | 世界的名字 |
| `canon` | 出自哪個作品；原創寫「原創」 |
| `scope` | 這份涵蓋的範圍（一座城、一個大陸、一個時代）。正典世界只寫原創的部分時，在這裡說清楚 |
| `sources[]` | `{ "what": "…", "covers": "…" }`：原作卷數、wiki、自己的設定文件 |
| `divergence` | 和原作不同的地方；原創的部分寫「原創：…」；沒有就寫「照原作」 |
| `story_time` | 這份描述的是故事裡哪個時間點 |
| `version`、`updated`、`notes` | 版本、日期、備忘 |

### 2.2 `overview`（導出成常駐總覽與索引）

| 欄位 | 寫什麼 | 送不送 |
|---|---|---|
| `one_line` | 一句：這是什麼樣的世界 | 索引、名片 |
| `basic` | 一段 ≤ 150 字：時代、地理、誰掌權、日常靠什麼、最大的不尋常 | **常駐** |
| `truths[]` | 3～6 句真相：讓這個世界不一樣的事，角色進場前就知道；每句直述、含名字 | **常駐** |
| `tone` | 基調與沉浸程度（寫實／誇張、喜劇／悲劇、解釋多／少） | 給寫手的提示詞，不當條目 |
| `speculative` | 唯一的推測性元素（最多一個） | 不送（審稿用） |
| `absent[]` | 整個世界沒有的東西 | **常駐**（併進 basic 之後，一行） |
| `undefined[]` | 還沒決定的 | 不送 |
| `calendar` | 有自己的曆法才寫 | 常駐或 `system` 實體 |

### 2.3 `entities[]`：每個實體都有的欄位

| 欄位 | 寫什麼 |
|---|---|
| `id` | `類型.名字`，例如 `place.巴斯庫拉`；`links`、`parent`、`clues` 用它互相指 |
| `type` | `place`／`faction`／`system`／`culture`／`species`／`event`／`item`／`concept` |
| `name`、`aliases[]` | 全名；別稱、通稱、簡體寫法（酒館沒有簡繁同用）。**別名列全**是觸發不漏的第一條件 |
| `tags[]` | 分類（地區、類別） |
| `parent` | 上一層實體的 id（子地點、分部、附屬組織） |
| `brief` | 短版 ≤ 60 字：名字、一句定位、最容易認出的特徵。導出到 `rp_brief` 與索引 |
| `common[]` | 常識，3～8 句。**每句含名字、每句獨立成立、直述句、現在式** |
| `lexicon[]` | 當地的說法：東西與方位的叫法、俚語、問候、咒罵；各一兩個。寫手與 NPC 說話的材料 |
| `local{}` | `known_by`＋`facts[]`，見 §1.3 |
| `secret{}` | `known_by`＋`facts[]`＋`clues[]`（哪三處能摸到這個真相：條目 id、人、物） |
| `absent[]` | 這裡沒有的（**送模型**，最可靠的一類事實） |
| `undefined[]` | 還沒定的（**不送模型**，給作者） |
| `links[]` | 往外指的鉤子：其他實體的 id，2～3 個；每個都要有條目或列入 `undefined` |
| `history[]` | `{ when（相對時間）, event, now（現在還看得到的後果或物證）, witnesses（誰在場／誰知道）}` |
| `now{}` | `as_of`、`situation`、`goals[]`（勢力：`{ goal, clock }`）、`portents[]`（若無人介入會依序看到的 3～5 步）、`doom`、`stakes`。**不進條目** |
| `keys{}` | `primary[]`、`secondary[]`、`conditions`（進階條件的算式，文字） |
| `export{}` | `book`（public／public＋truth）、`constant`、`position`、`recursion`、`brief_mode` |
| `source`、`as_of` | 出處；這筆的時間點和 `meta.story_time` 不同時才寫 |

### 2.4 各類型的必填欄位

**`place` 地點**：`features[]`（三個最容易認出的特徵：看得到、聽得到、聞得到的）、`access[]`（出入口與鄰接，至少兩個，一個不明顯的）、`can_do[]`、`rules[]`（規矩、價格、禁忌；數值只寫在這裡）、`rulers{ apparent, real }`、`people[]`（常見的人：類型與狀態，不寫個體，≤ 3 群——這就是 `角色分級_寫作說明.md` §4 的背景人物）、`dangers[]`。

**`faction` 勢力**：`impulse`（一句：想要什麼）、`tier`、`hold`、`assets[]`、`turf`、`leaders[]`（`{ name, role, trait }`）、`allies[]`、`enemies[]`、`public_face`、`inside[]`（成員才知道的＝這個勢力的在地層）、`membership`。目標與時鐘在 `now.goals`。

**`system` 制度**（魔法、科技、法律、經濟、曆法、宇宙觀）：`hardness`（硬／軟）、`can[]`、`limits[]`、`weaknesses[]`、`costs[]`、`access`、`consequences[]`（對社會的後果）、`perceived`（一般人看到的樣子，感官不是機制）。軟的寫明「故事裡不拿來解決問題」。

**`culture` 文化／族群／信仰**：`traits[]`（三個，`{ trait, because }`：各附環境或歷史上的原因）、`values[]`、`taboos[]`、`customs{ greeting, food, dress, calendar, death }`、`power`、`variation`（內部差異）、`stereotype`／`truth`。

**`species` 種族／生物**：`habitat`、`abilities[]`、`limits[]`、`rarity`（常見／罕見／稀有／唯一：決定誰認得出、認出後知道多少）、`relations[]`、`folklore[]`／`fact[]`。

**`event` 事件／歷史**：`when`（相對時間）、`cause`、`consequences_now[]`、`evidence[]`（物證）、`accounts[]`（`{ who, believes }`：各方相信的版本）、`witnesses`；真正發生的事放 `secret.facts`。

**`item` 物品／材料**：`origin`、`does`、`cost`、`holder`、`wanted_by[]`、`problems[]`（它製造了什麼新問題）、`appearance`。

**`concept` 前提**：`truth`（採用的說法）、`excluded[]`（排除的替代說法）、`daily[]`（日常怎麼顯現）、`tone`。通常常駐、不設關鍵字。

## 3. 導出對照表

### 3.1 四種產物

| 產物 | 從總表拿什麼 | 條目設定 |
|---|---|---|
| **總覽**（公開書，1～3 條） | `overview.basic`＋`truths`＋`absent` 一行；超過 150 字拆成「總覽」與「真相」兩條 | 常駐、角色前、order 最高；名稱 `總覽｜［世界名］` |
| **索引**（公開書，1 條；引擎做出 docs/18 B2 之前先手寫） | 每個實體一行：`name`：`brief` 第一句 | 常駐、角色前；名稱 `索引｜［世界名］`；超過 20 個實體時改成只列地點與勢力 |
| **公開條目**（公開書，每個實體 1 條） | `brief` → 短版；內容＝`common`＋該類型必填欄位＋`lexicon`＋`local`（併入或另立）＋`absent` | 觸發、角色前；名稱 `類型｜［名字］`；`keys` 照 §4 |
| **在地條目**（可選） | `local.facts` 名單很窄、或超過 3 句時另立 | 觸發；名稱 `類型｜［名字］在地`；關鍵字＝實體名＋限定（打聽、問、老人、傳說） |
| **真相條目**（**真相書**，有 `secret` 的實體各 1 條） | `secret.facts`＋一行「線索：…」（`clues`） | 觸發（同實體的 keys）或常駐；名稱 `類型｜［名字］真相`；**不勾常駐時也只綁寫手與推演** |
| **推演種子**（不是條目） | 每個實體的 `now`；`overview.tone` | 給劇情推演（docs/21）的「世界裡正在進行的事」；主線模板（docs/28）引用實體 id |

**兩本書怎麼綁**：公開書 → 全域啟用（寫手、NPC、一般聊天都看到）。真相書 → 不全域啟用，只在工作流裡勾給寫手節點與劇情推演節點的私用世界書。NPC 節點看不到真相書，他該知道的真相寫在他自己的 `［全名・私密］`。

### 3.2 一條公開條目的樣子

欄位順序**全書一致**（格式一變準確率就掉）。沒有內容的行省略。

```
標題：地點｜［名字］
短版：brief
內容：
名字（別稱）是……。                       ← common 第 1 句：一句定位
樣子：features 三個，一行。
出入：access。
能做的事：can_do。
規矩與價格：rules。
誰管事：rulers（apparent；實際上 real）。    ← 未定的不寫
常見的人：people。
（其餘 common 句子）
當地的說法：lexicon。
○○才知道：local.facts（含「誰說的」）。     ← 併入時
這裡沒有：absent。
```

勢力：`名字是……。／想要：impulse。／規模：tier、hold。／地盤與資產：turf、assets。／領袖：leaders。／盟友與敵人。／外人看到的：public_face。／成員才知道：inside。／當地的說法。／沒有：absent。`

制度：`名字是……。／能做：can。／做不到：limits。／會被什麼反制：weaknesses。／代價：costs。／誰學得到：access。／對世界的影響：consequences。／一般人看到的：perceived。／術語：lexicon。／硬／軟：一句。`

事件：`名字（相對時間）：發生了什麼。／起因：cause。／現在：consequences_now。／物證：evidence。／各方的說法：accounts。／誰知道：witnesses。`

其他類型照同樣的邏輯：第一句定位，接著必填欄位各一行，最後用語與「沒有」。

### 3.3 真相條目的樣子

```
標題：地點｜［無聲迴廊］真相        可見性：只給寫手與劇情推演
短版：（不用）
內容：
無聲迴廊的真相：
secret.facts 逐句。
誰知道：secret.known_by。
線索：clues（寫手可以從這些地方讓玩家摸到）。
```

## 4. 關鍵字與設定

照 docs/19 §4.5.1 的規則，加上世界觀專用的三點：

1. **實體名＝錨點**，別稱列全。有唯一性的名字（巴斯庫拉、無聲迴廊、果爾）單獨觸發。
2. **通稱要限定**。「旅店」「公會」「迷宮」「影子」每個世界都有，單獨當主鍵會在別的場景命中。寫成進階條件：`(專名) | ((通稱…) & (上層地點或這類話題)［最近 4 則］)`，照 `總武高中/說明.md` 的做法；酒館沒有進階條件時引擎會編成正則。
3. **子實體靠上層帶出**：巴斯庫拉的條目內容提到歪角亭、無聲迴廊、公會，遞迴時帶出它們的短版；它們的全文要等玩家真的提到。總覽的內容提到城的名字，帶出城。超過 300 字的條目勾「不觸發其他條目」。

設定：

| 項目 | 怎麼設 |
|---|---|
| 位置 | 總覽、索引、公開條目、真相條目都放**角色前**；開「非常駐條目放聊天紀錄之後」時引擎會自動把觸發的搬到尾端。**不放 @深度** |
| 常駐 | 只有總覽與索引；concept 類型可以常駐。問自己：「每一句對話都需要模型記得這一條嗎？」 |
| 順序 | 總覽 > 制度與前提 > 地點與勢力 > 物品、事件、種族。酒館的 order 越大越靠尾端、越重要 |
| 短版 | 每條都寫；遞迴帶出與預算不夠時引擎送短版 |
| 掃描深度 | 專名條目照全域；通稱限定的那一組看［最近 4 則］（地點話題會延續幾則）；物品、甜食這類一閃而過的看［最近 2 則］ |
| 簡繁同用 | 本引擎開著就好；要匯到酒館的，`aliases` 補簡體寫法 |

## 5. 範例（從 `世界觀總表_巴斯庫拉.json` 導出）

### 5.1 總覽（常駐）

```
標題：總覽｜［巴斯庫拉］
內容：
巴斯庫拉是魔大陸上一座建在巨大裂谷兩側崖壁上的魔族城市，靠谷底迷宮「無聲迴廊」出產的高濃度魔石養活，比一般魔大陸城鎮富裕。多種魔族混居，人族極少，通用語是魔神語。城分崖頂、棧道、谷底三層，白天只有正午前後陽光照得到谷底。
巴斯庫拉的一切都圍著魔石：帶回多少魔石決定你在這座城的地位，沒人在意你是什麼種族。
無聲迴廊越往下越安靜，第八層以下連隊友喊危險都聽不見，下去的隊伍幾乎都沒回來。
巴斯庫拉的食物是魔大陸水準：烤陸龜肉、岩蜥串、菇湯、硬得能當武器的黑麵包；甜食極少。
巴斯庫拉的治安普通：城裡打架有城主的衛兵管，迷宮裡出事沒人管。
人族走在巴斯庫拉街上會被多看兩眼，沒人會特別找麻煩。
巴斯庫拉沒有人族的教會、沒有城牆（裂谷本身就是牆）、沒有甜點店。
```
約 230 字。再長就把真相五句拆成第二條。

### 5.2 索引（常駐，手寫版）

```
標題：索引｜［巴斯庫拉］
內容：
```

## 6. 檢查表

- [ ] `overview.basic` ≤ 150 字；`truths` 3～6 句，每句有名字。
- [ ] 每個實體有 `brief`（≤ 60 字）、`common`（3～8 句）、該類型的必填欄位。
- [ ] `common` 每句含實體名或人名，沒有一句用「它／那裡／這座城／他們」開頭。
- [ ] `common` 與 `secret` 沒有「可能／也許／據說」；這些只在 `local.facts` 裡，而且寫了誰說的。
- [ ] `secret.facts` 的句子沒有漏進 `common` 或 `local`；每個 `secret` 有 ≥ 3 條 `clues`。
- [ ] 每個 `links` 的 id 都有條目，或列在 `undefined`；`undefined` 的東西沒有出現在 `common`。
- [ ] `now` 的內容沒有出現在 `common`（檢驗：三十回合後這句還對嗎？）。
- [ ] `system` 類型有 `limits`、`weaknesses`、`costs` 各至少一條，有 `hardness`。
- [ ] `place` 類型 `access` ≥ 2、`people` ≤ 3 群、`features` 剛好 3 個。
- [ ] `culture` 類型 `traits` 剛好 3 個，每個有 `because`。
- [ ] 通稱（旅店、公會、迷宮、影子）當關鍵字的條目，`keys.conditions` 有上層地點或話題的限定。
- [ ] `aliases` 含簡體寫法（要匯到酒館的）。
- [ ] 條目名稱括號裡沒有「・」「×」（有的話引擎會當成角色）。
- [ ] 導出的公開條目 ≤ 500 字、欄位順序全書一致；超過的拆子條目。
- [ ] 沒有值為 null、空字串、空陣列的欄位——用不到就刪（範例檔為了示範留了幾個空的 `secret`，自己寫時刪掉）。
