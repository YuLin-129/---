# 角色總表：主要角色的完整資料格式
> 撰寫：claude-fable-5-1（effort high）・2026-10-25

> **角色總表**是一個角色調查完之後寫成的完整檔案（JSON），目的是**最大還原**。它不直接送給模型；要用的時候從它**導出**成別的東西：主要角色的六層角色包（docs/19 §4.1）、配角的核心八行、路人的名片（`角色分級_寫作說明.md`）、或酒館的單人卡。
> 這份說明：第 1 節是和你現在的格式比哪裡改了、為什麼；第 2 節是欄位；第 3 節是導出對照表；第 4 節是檢查表。空白骨架在 `角色總表_模板.json`，完整範例在 `角色總表_姬絲秀忒.json`（內容照你的卡，只換格式）。

---

## 1. 和現在的格式比：改了什麼、為什麼

你的格式（十三個區塊）內容是對的——docs/19 §0 已經講過，論文裡對還原度最有效的東西它有四樣。下面只動**格式**，讓它更好導出、更少內部矛盾、更能撐長期維護。

| # | 改動 | 原本 | 為什麼 |
|---|---|---|---|
| 1 | **加 `meta`**：來源、時間點、版本 | 沒有 | 調查完的資料要能追：哪些是原作、哪些是你自創、哪些是推測。總表會改很多次，沒有版本與時間點，之後分不清哪一份是對的 |
| 2 | **每個區塊加 `summary` 一句** | 沒有 | 導出時直接變成名片、短版、核心卡的一行；寫的時候也逼自己先想清楚這一塊的重點 |
| 3 | **加 `voice.examples[]`：範例對話** | 只有 `catchphrases` | docs/19 §2.1：範例當成真的對話回合，勝率 29.8% → 63.3%；是你格式唯一缺的那一樣。每段：情境＋對方的話＋她的話，3～8 段，覆蓋不同情緒 |
| 4 | **`patterns[]` 搬到最上層，加 `keywords`** | 藏在 `behavior.distinctive_patterns` | 它是導出情境條目的直接來源（情境→解讀→反應→例外），每則加上觸發詞，導出時不用再想關鍵字 |
| 5 | **關係合併成一處**：`relationships[]` 吃進 `speech.addressing`、`person_specific_differences` | 同一個人的資料散在三個地方 | 三處會互相矛盾（改了一處忘了另兩處）；導出關係條目時也只要看一個地方。每筆加 `category`（家人／朋友／熟人／陌生／敵對）、`trust` 0～10、`visibility` |
| 6 | **加 `visibility`**：公開／誰知道／私密 | 沒有；`knows_but_hides`、`unspoken_thoughts` 散在各處 | NPC 節點只拿私密、寫手拿公開，是引擎已經在做的事（docs/19 §4.10）；標在資料上，導出時才知道每一筆該放哪一層 |
| 7 | **`history[]` 每件加 `when`、`known_by`** | 只有 event／impact／current_effect | 時間點讓「視野截止」可以算；誰知道這件事決定它是公開條目還是私密 |
| 8 | **`knowledge` 加 `cutoff`、`when_unsure`** | 五個清單 | 知識邊界最重要的是**截止在哪個時間點**與**不知道時怎麼答**（CHARM：先說視野再回答 10% → 80%）；清單留著 |
| 9 | **守則改成正面句＋理由**：`rules[]`；禁止清單降級為 `review_checks[]`（審稿用，不導出） | 四組 1,225 token 幾乎全是「不得」 | docs/19 §2.3：禁止令漏 13～36%，點名要避免的東西反而提醒模型去做。審稿清單對人有用，所以留著，但標明不送 |
| 10 | **`identity` 改成通用欄位＋`extra`** | 寫死 school／year／halo（校園設定的欄位） | 不同世界觀的角色不該共用校園欄位；設定專屬的放 `extra` 自由鍵值 |
| 11 | **加 `big_five`** | 沒有 | 一行就能穩定改變行為（PersonaLLM、Big5-Chat），導出時放核心卡最後一行 |
| 12 | **`now` 區塊**：現況、目前目標、目前的關係狀態，標 `as_of` | 混在 identity.current_status 與 motivations.current_goals | 這些是**會變的**。單獨一塊、標時間點，開新故事時只改這裡；其餘區塊是不變的本質 |
| 13 | **不留 null**：用不到的欄位直接刪，不要留 null 或空字串 | 一堆 null | null 沒有資訊，還會讓 AI 寫的時候硬填。身高、三圍這些欄位保留：有官方數字就填官方，沒有公開官方資料就依角色圖片推測並在 `measurements_source` 標明；姬絲秀忒的範例寫在這條規則之前，所以沒有這兩個欄位 |

沒改的：`personality`（core／surface／inner／self_image／conflicts／insecurities／contrasts）、`thinking`、`motivations` 的主體、`daily_life`、`abilities`——結構對，照搬。

**為什麼還是 JSON**：給人看、給程式導出，JSON 最方便；送出時從來不是原樣送。

## 2. 欄位

頂層順序固定；不適用的區塊整塊省略，不要留空物件。所有文字繁體中文、台灣用語。

### 2.1 `meta`

| 欄位 | 寫什麼 |
|---|---|
| `canon` | 出自哪個作品；原創寫「原創」 |
| `sources[]` | 調查用了什麼：原作卷數、wiki、你的設定文件。每筆 `{ "what": "…", "covers": "這份來源涵蓋的部分" }` |
| `divergence` | 和原作不同的地方，一段。沒有就寫「照原作」 |
| `story_time` | 這份總表描述的是角色在故事裡**哪個時間點**（例如「甦醒後第 7 天」） |
| `version`、`updated` | 版本號、日期 |
| `notes` | 給自己的備忘 |

### 2.2 `identity`

`name`、`aliases[]`、`age`、`race`、`gender`、`affiliation`（現在屬於哪裡）、`position`（身分／頭銜）、`role`（一句：他在故事裡是什麼）、`summary`、`extra{}`（世界觀專屬：學校、班級、職階……）。

### 2.3 `appearance`

`summary`（一句，導出用）、`height_cm`、`measurements_cm{ bust, waist, hips }`、`measurements_source`（有官方數字就填官方並寫出處；沒有公開的官方資料時，依角色圖片——立繪、各服裝立繪、劇情 CG——推測，`measurements_source` 寫明「依角色圖片推測」、看了哪些圖、和哪個已知數據的角色比較、大約誤差）、`body`、`hair`、`eyes`、`skin`、`racial_traits`、`distinctive_features[]`（3～8 個）、`expression`、`posture`、`outfits{}`（`default` 必填，其他狀態自由命名）、`forms{}`（外形會變的角色：每種形態一段；不會變就省略）。

### 2.4 `personality`

`summary`、`core`、`surface`、`inner`、`self_image`、`contrasts[]`（3～8 組「A × B」）、`conflicts[]`、`insecurities[]`、`emotional_style`（情緒怎麼表現）、`big_five`（一行：外向／親和／盡責／神經質／開放，各寫高中低）。

### 2.5 `thinking`

`summary`、`style`、`attention[]`（她先注意什麼，排序）、`decision`、`values[]`（排序）、`risk`、`social`、`when_unsure`（資訊不足時怎麼做）、`blind_spots[]`、`belief_revision`（什麼能改變她的想法、什麼不能）。

### 2.6 `motivations`

`summary`、`drives[]`（長期驅動力）、`long_term[]`、`protects[]`、`avoids[]`、`bottom_lines[]`——**每條寫成 `{ "line": "…", "because": "…" }`**，正面寫。目前的目標不在這裡，在 `now`。

### 2.7 `voice`

| 欄位 | 寫什麼 |
|---|---|
| `summary` | 一句聲線 |
| `style` | 整體語氣、用語年代感、句子長短 |
| `self_reference[]` | 自稱 |
| `address_default` | 對陌生人、對一般人怎麼叫（對特定人的稱呼寫在 `relationships[].address`） |
| `rhythm` | 節奏、說話的習慣順序（例如「先評論再回答」） |
| `habits[]` | 口語習慣 |
| `catchphrases[]` | 口頭禪 3～6 句 |
| `humor` | 怎麼開玩笑 |
| `by_emotion{}` | 開心／惱怒／悲傷／憤怒／害羞時各怎麼說話 |
| `serious_mode` | 認真時變成什麼樣 |
| `examples[]` | **範例對話** 3～8 段：`{ "situation": "…", "other": "對方說的話", "self": "她的回應（含動作）", "shows": "這段展示的是什麼" }`。要覆蓋：日常、情緒失守、嚴肅模式、知識邊界（被問到不知道的事）、底線被碰到 |

### 2.8 `patterns[]`

情境→解讀→反應。每則：

```json
{ "situation": "…", "reading": "她怎麼解讀", "response": "她怎麼做、怎麼說", "exception": "什麼情況例外", "keywords": ["觸發詞", "…"] }
```

5～12 則。`keywords` 是導出情境條目時的主要關鍵字，照 docs/19 §4.5.1 寫錨點（少而具體）。

### 2.9 `behavior`

一般情境下的樣子：`daily`、`with_strangers`、`with_friends`、`with_close`、`under_pressure`、`in_conflict`、`in_crisis`、`when_emotional`、`in_private`。每項一到三句。

### 2.10 `relationships[]`

每個人一筆：

| 欄位 | 寫什麼 |
|---|---|
| `name` | 對方全名；`aliases[]` 對方的別名（導出關鍵字用） |
| `category` | 家人／戀人／朋友／熟人／陌生／敵對／（自訂） |
| `relation` | 關係是什麼，一句 |
| `view` | 她怎麼看對方 |
| `tone` | 情緒基調 |
| `typical` | 平常怎麼互動 |
| `address` | 她怎麼叫對方（從原本的 `speech.addressing` 搬來） |
| `in_presence` | 對方在場時她會變成什麼樣（從 `person_specific_differences` 搬來） |
| `trust` | `{ "value": 0～10, "note": "…" }` |
| `conflicts` | 會起摩擦的地方 |
| `unspoken` | 沒說出口的 |
| `visibility` | `public`（寫手與所有人可見）／`private`（只有她自己的節點）／`known_by: [...]` |
| `as_of` | 這筆關係描述的時間點（會變的關係要標） |

### 2.11 `daily_life`

`likes[]`、`dislikes[]`、`interests[]`、`habits[]`、`lifestyle`、`money`、`possessions[]`。

### 2.12 `abilities`

`summary`、`strengths[]`、`weaknesses[]`、`skills[]`（每項 `{ "name": "…", "detail": "…" }`）、`combat{ role, style, iq, weapon, equipment[] }`、`limits[]`（正面寫：「再生要消耗魔力與生命力，不是無限的」）。

### 2.13 `history[]`

每件：`{ "when": "時間點（絕對或相對）", "event": "…", "impact": "當時造成什麼", "now": "對現在的影響", "known_by": "public ／ private ／ 名單" }`。照時間排。`known_by` 的值和 `relationships[].visibility` 用同一套：`public`（大家都知道）、`private`（只有她自己知道）、或知道的人的名單；可以在後面加括號註記。

### 2.14 `knowledge`

| 欄位 | 寫什麼 |
|---|---|
| `cutoff` | 她的視野截止在哪個時間點、為什麼 |
| `knows[]`、`unknown[]`、`misreads[]` | 知道／不知道／會誤判的 |
| `hides[]` | 知道但不說（每條可加 `tells_if`：什麼條件下會說） |
| `suspects[]` | 懷疑的 |
| `secrets[]` | 連自己都不太承認的 |
| `when_unsure` | 碰到不知道的事怎麼答（「先確認是不是她睡著以後的事，再用舊印象答或說不知道」） |

### 2.15 `now`

會變的東西，開新故事或換時間點時只改這裡：`as_of`、`status`（現況兩三段）、`goals[]`（目前的目標）、`emotional_state`（此刻的基調）、`open_threads[]`（還沒解決的事）。

### 2.16 `rules[]` 與 `review_checks[]`

- `rules[]`：扮演時要守住的事，**正面寫、附理由**，10～25 條：`{ "rule": "…", "because": "…" }`。導出時挑 5 條進角色備註，其餘融進核心卡。
- `review_checks[]`：審稿用的「常見誤寫」清單，寫法自由（可以用否定句），**不導出、不送模型**。

## 3. 導出對照表

| 目標 | 從總表拿什麼 |
|---|---|
| **名片**（一行） | `identity.name`、`aliases`、`identity.summary` |
| **核心卡**（≤ 1,200） | `identity.summary`、`appearance.summary`、`personality.core/surface/inner`、`contrasts` 挑 3、`thinking.style/decision/when_unsure`、`voice.summary/style/self_reference/rhythm/catchphrases`、`motivations.bottom_lines`（含 because）、`big_five` |
| **範例台詞**（3～5 段） | `voice.examples` 挑覆蓋面最廣的 |
| **角色備註**（深度 2，≤ 150） | `rules` 挑 5＋`knowledge.cutoff` 一句 |
| **關係條目**（每人一條） | `relationships[]` 一筆一條；主鍵＝對方 `name`＋`aliases`；`visibility: private` 的 `unspoken` 另拆進私密 |
| **情境條目** | `patterns[]` 一則一條；主鍵＝`keywords` |
| **經歷條目**（3～4 條） | `history[]` 依主題合併；`known_by` 不是 public 的進私密 |
| **能力／外觀／喜好條目** | `abilities`、`appearance`、`daily_life` 各一條 |
| **視野條目** | `knowledge.cutoff/knows/unknown/misreads/when_unsure` |
| **私密條目** | `knowledge.hides/suspects/secrets`＋所有 `visibility: private` 的欄位 |
| **動態（記憶／紀錄）** | `now` |
| **配角核心八行** | 名字←`identity.name`；定位←`identity.role`；外觀←`appearance.summary`；個性←`personality.surface`＋`inner` 挑一件；說話←`voice.summary`＋一句 `catchphrases`；想要←`now.goals[0]`；對主角←`relationships` 裡主角那筆的 `view`；界線←`bottom_lines[0]` |
| **路人名片** | `identity.name/role`、`appearance.summary`、`voice.summary`、`daily_life.habits` 挑一個 |

## 4. 檢查表

- [ ] `meta.story_time` 和 `now.as_of` 一致；`history` 最後一件不晚於這個時間點。
- [ ] 每個區塊有 `summary`，而且是一句話。
- [ ] `voice.examples` 至少 3 段，其中有一段是「被問到不知道的事」、一段是底線被碰到。
- [ ] `bottom_lines`、`rules` 全部是正面句＋理由；否定句只出現在 `review_checks`。
- [ ] 同一個人的稱呼、態度只寫在 `relationships[]` 那一筆，`voice` 裡沒有重複。
- [ ] 每筆 `relationships`、`history` 都有 `visibility`／`known_by`。
- [ ] `knowledge.cutoff` 寫得出具體時間點。
- [ ] `identity.extra` 以外沒有世界觀專屬的欄位名。
- [ ] 沒有值為 null 或空字串的欄位——用不到就刪。
- [ ] `patterns[].keywords` 每則 2～5 個，沒有一長串的「或」。
