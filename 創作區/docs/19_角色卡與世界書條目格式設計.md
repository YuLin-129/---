# 角色卡與世界書條目的寫法：研究與本引擎的格式設計

> 2026-10-18。**只研究與設計、不改程式。** 使用者給了自己的角色卡格式（JSON，十三個區塊）與範例（姬絲秀忒，15K token）和一本角色世界書（`characters_k417_worldbook.json`，18 條時間點快照），要求：以本引擎為準設計角色卡該怎麼呈現、世界書條目該怎麼寫；重點是**角色還原度、角色的思考、情感重量**。

## 0. 先講結論

1. **你的格式內容是對的，問題在「怎麼送」。** 論文裡對還原度最有效的五樣東西，你的格式已經有四樣：情境→解讀→反應的模式（`distinctive_patterns`）、動機（`motivations`）、知識邊界（`knowledge`）、守則（`portrayal_guardrails`）。缺的一樣是**範例台詞**：把台詞當成真的對話回合送，角色扮演勝率從 29.8% 升到 63.3%（RoleLLM）；只靠描述寫聲線是最弱的做法。
2. **JSON 不是問題，但也沒有好處。** 你的卡 JSON 15,253 token，改成「欄位：內容」行 14,264，只差 6%；論文裡結構化與散文的差距 ≤ 0.07 分。結構留給**人看與分層**，送出時用「欄位：內容」行或短散文。
3. **真正的三個問題**：
   - **全部常駐**：15K token 每回合都送，中段會被忽略（答案在中間時準確率從 75.8% 掉到 53.8%，比不給還低）；而且 9,014 token 是情境性的（關係、經歷、模式、知識、能力、外觀），只在相關時才需要。
   - **否定句太多**：卡片 434 行裡 76 行、世界書每條 10 行裡 5～9 行是「不得／不要／不應」。論文：禁止令漏 13%～36%，而且**點名要避免的東西會提醒模型去做**；87.5% 的違規是指令本身造成的。
   - **沒有這一幕的狀態**：動機、情緒、信任是每幕會變的東西，寫死在卡上會過期。CoSER 拿掉「這一幕的動機」掉 1.4～3 分；拿掉「說話前的內心」掉 1.7～3 分；有明確情緒狀態的代理人，人類偏好 48：23。
4. **建議的資料結構：角色包（一個角色＝六層）**，對應本引擎現有的位置：

   | 層 | 內容 | 放哪裡 | 什麼時候送 | 大小 |
   |---|---|---|---|---|
   | 0 名片 | 一行：名字、別名、一句定位 | 索引（`18` B2） | 常駐 | 25 token |
   | 1 核心卡 | 本質、聲線、思考方式、底線（正面寫） | 角色卡 `description` | 常駐（快取） | ≤ 1,200 |
   | 2 範例台詞 | 3～5 段不同情緒的對話 | `mes_example` | 常駐 | ≤ 600 |
   | 3 角色備註 | 5 條最重要的守則（正面）＋知識視野一句 | `depth_prompt` 深度 2 | 常駐、靠近尾端 | ≤ 150 |
   | 4 情境條目 | 關係（每人一條）、模式（合併 2～4 條）、經歷（3～4 條）、能力、外觀、喜好 | 世界書（角色包） | 觸發、在場、語意 | 每條 ≤ 400＋短版 |
   | 5 私密條目 | 知道但不說、祕密、懷疑、未說出口 | 世界書，標「私密」 | 只給這個角色的 NPC 節點 | 每條 ≤ 300 |
   | 6 動態狀態 | 現況、這一幕的動機、情緒、信任 | 記憶插件條目、工作流紀錄、規劃節點 | 每幕更新 | 每個角色 ≤ 100 |

   姬絲秀忒拆完：常駐 ≈ 1,900 token（現在 15,253），情境條目 ≈ 9,000 token 分成 20 多條按需要送、每條有 150 字短版。
5. **條目的寫法**：一條一主題；名字寫進內容；正面句＋理由；時間戳當標題、有效期當欄位；150～400 token；關鍵字列全部別名（繁簡、暱稱）。你的 K417 快照結構（身分／外觀／性格／說話／現況／能力／關係／知識／活動）很好，只要把否定句改成「此時是什麼」。
6. **思考與情感**要做在三個地方，不是卡上：規劃節點每幕產出每個在場角色的「此刻想要什麼」與情緒（標籤＋強度＋一句原因）；NPC 與寫手的私密 `<thought>` 分段（短、用角色口吻、錨定動機，不是通用的推理）；關係的信任值放在紀錄裡（模型會把高信任變成偏袒、低信任變成敵對，所以要刻意設）。
7. **兩種包裝**（使用者 2026-10-18 補充：角色卡主要是給 NPC 節點用的，但不是所有 NPC 都走節點，路人由寫手演；之後可能路人走通用 API、主要角色各自有 API）：同一個角色包可以做成 **A 主要角色版**（NPC 版世界書只給她的節點＋公開版世界書給寫手與其他 NPC）或 **B 路人／通用版**（全部放世界書，寫手自己演）。差別只在關鍵字（A 只有她一本，主鍵直接用情境詞；B 與人共用，主鍵是她的名字、次要鍵是情境詞）與誰看得到。樣板在 `docs/samples/姬絲秀忒_角色包.md` 與同目錄的三本世界書＋一張單人聊天卡（§4.9）。
8. **引擎要配合的**（第 5 節）：角色包匯入精靈（把你的 JSON 一鍵拆成六層）、條目模板、私密條目的開關、在場觸發、角色備註自動化、否定句提示、規劃節點多兩個任務。寫法本身零成本，今天就能用。

## 2. 論文怎麼說

### 2.1 哪些欄位真的有用

| 項目 | 證據 | 數字 | 對你的格式 |
|---|---|---|---|
| **範例台詞當成真的對話回合** | RoleLLM（2024） | 零樣本 9.3 → 把範例寫進指令 29.8 → 範例當成先前對話 63.3（GPT-4 評審勝率） | 你的卡沒有範例；`catchphrases` 不夠，要 3～5 段完整的往返 |
| **這一幕的動機** | CoSER（ICML 2025） | 拿掉每幕動機 59.06 → 57.71；未微調的 70B 模型掉 3.0 | `current_goals` 是全局的；每幕的「此刻想要什麼」要動態產生 |
| **說話前的內心** | CoSER；Thinking Before Speaking（AAAI 2025）；MIRROR（2025）；RAR（NeurIPS 2025） | CoSER 拿掉內心 −1.7；TBS 拿掉心境資料邏輯分 6.45 → 4.70；MIRROR 讓 Claude 3.5 在 LifeChoice 58.1 → 64.4；RAR 先把角色資料轉成「情緒／經歷／立場／動機」再推理 3.19 → 3.69，純推理模型反而「忘了角色、語氣變正式」 | 內心要短、用角色口吻、錨定動機；通用的推理鏈會傷聲線 |
| **情境→解讀→反應** | MRPrompt（ACL 2026） | 「線索 → 表現 → 邊界」的結構化綱要讓 Qwen3-8B 追上 GLM-4.7；綱要的貢獻大於流程 | 你的 `distinctive_patterns` 正是這個，保留，改成觸發式條目 |
| **描述是骨幹、台詞是加成** | InCharacter（ACL 2024） | 只有描述 71.3%，描述＋檢索台詞 72.0%，只有台詞 71.9%（16P 掉到 79.3 → 71.9 的反例） | 兩個都要；描述先、台詞再加 |

| **把資料對齊場景** | Beyond Dialogue（2024） | 83.2% 的對話至少有一個資料裡的特徵在那一幕根本沒出現；對齊後合格率 37.3 → 56.3 | 永遠送整張卡＝每一幕都帶一堆沒用到的特徵；情境條目解決這個 |

### 2.2 格式與長度

- 結構化 vs 散文：同一份 590 字的資料，PersonaGym 差 ≤ 0.07，CoSER 互有勝負（Jun 等 2026）。He 等（2024）：GPT-4 對格式不敏感，JSON 會讓某些模型少寫正文。廠商：Anthropic 建議 XML 標籤分段、3～5 個範例；OpenAI 說「JSON 對文件類輸入表現特別差」、指令放頭尾。
- 長度：沒有論文直接變化角色卡長度（未驗證的缺口）。旁證：Lost in the Middle 首 75.8%／中 53.8%／尾 63.2%；Same Task More Tokens 在 3,000 token 就從 0.92 掉到 0.68。社群：常駐欄位 1,000～1,500 token（tavernsprite、aituts 2026）、描述 200～500 中文字（知乎）；長卡的真正風險是**內部矛盾**（Trappu、2026 的討論）。
- **結論**：常駐 ≤ 1,500 token，其餘按需要；守則與聲線放頭尾；格式一旦選定每回合不變（Sclar 等：只換分隔符就能差 76 個百分點）。

### 2.3 否定句

| 證據 | 數字 |
|---|---|
| Negated prompts（2022） | 否定指令的準確率隨模型變大反而更差；「做 X」與「不要做 X」被當成一樣 |
| Suppressing Pink Elephants（2024） | 系統提示禁止某話題：Llama-2-13B 仍提到 25%（不禁 33%）、GPT-4 13%、OpenHermes-7B 反而從 33% 升到 36%；**點名禁止的東西讓模型更可能提到它** |
| Semantic Gravity Wells（2026，單一模型、未審） | 「不要用某個詞」的違規率隨那個詞的基礎機率從 9% 升到 46%；87.5% 的違規是指令本身造成的 |
| 廠商 | Anthropic：「告訴它要做什麼，不是不要做什麼」並附理由；OpenAI 仍允許列「絕不」，但說一句明確的期望行為通常就夠 |

**結論**：`avoid`、`common_mistakes`、`do_not_exaggerate`、`do_not_reduce_to` 四組（1,225 token）改寫成「她是什麼」＋理由；真的必須禁止的留 3～5 條放角色備註；要避免的概念**盡量不點名**；點了名的預期 10%～25% 會漏。

### 2.4 情感與人格

- 明確的情緒狀態有用：Humanoid Agents 用情緒標籤＋需求 0～10＋親密度 0～30，人類判定情緒 F1 0.84；CPM-MultiAgent 用 8 種情緒 × 1～5 強度、每回合做評估更新，人類偏好 48：23；Beyond Dialogue 拿掉情緒對齊合格率 56.3 → 48.7；RoleCraft 加情緒標註有提升。**靜態的「情緒表達方式」描述沒有這個效果**，要的是每幕更新的小狀態。
- 五大人格一行就能穩定改變行為（PersonaLLM、Big5-Chat）；MBTI 只能回收約 65%（CharacterEval），當粗略指標。
- 反面：ERABAL 用邊界陷阱訓練讓拒答 0.72 → 0.88，但同理心 2.97 → 2.76——守則太硬會壓掉情感。

### 2.5 知識邊界

| 證據 | 數字 | 做法 |
|---|---|---|
| TimeChara（ACL 2024） | GPT-4o 零樣本時空一致只有 64.5%（未來事件 46%）；加「敘事專家＋檢索截止」87.5%（未來 95.5%） | 時間戳＋只給那個時間點以前的資料 |
| CHARM（2026） | GPT-4o 認得出邊界 91.3%，但遵守只有 18.9%；**先讓角色說出自己的視野再回答** 10.4% → 80.6% | 備註裡一句「回答前先確認這是不是她視野內的事」 |
| Character-LLM | 不到 100 個「被問到年代外的事時表示不知道」的範例就能壓住幻覺 | 範例台詞裡放一段「被問到不知道的事」 |
| ReverieMem（2026） | 事實標「誰看得見」+34.6 個百分點 | 私密條目＝可見性標記 |
| SOTOPIA（ICLR 2024） | 關係類別決定能看到對方資料的哪些部分（朋友看全部但不含祕密、陌生人什麼都看不到） | NPC 節點的條目可見性照關係決定 |

### 2.6 關係

- 沒有論文直接比較「數值 vs 散文」的關係表示。證據支持三件事：**類別**（家人／朋友／戀人／點頭之交／陌生人）決定資訊可見性（SOTOPIA）；**立場值**會被模型忠實變成偏袒或敵對——高好感時連錯的話都附和 53.4%（SHARP），所以要刻意設；**散文的「怎麼看他／語氣／沒說出口的」保留**，Beyond Dialogue 拿掉親密度只掉 5.7，拿掉性格掉 11.7。
- 你的 `relationships` 欄位（view／tone／typical／trust／conflicts／unspoken）正好是散文＋一個可以數值化的 trust，結構對；問題只是 7 人 2,140 token 永遠送。

### 2.7 長對話的漂移

- 8 回合內人格就開始漂移，模型對系統提示的注意力隨回合衰減（Li 等 2024）；100 回合後角色特有的用詞模式掉 41.27%（Persistent Personas，EACL 2026）。
- 對策：定期**再錨定**——角色備註放深度 2（每回合都在尾端附近）、情境條目在聊天紀錄之後（`18` C1）、記憶插件的條目觸發。這就是為什麼第 3 層角色備註不能省。

## 3. 社群怎麼做（2024–2026）

- **格式**：W++ 已死（每個 2023 以後的指南都這麼說：浪費 token、模型會模仿括號語法）；PList 只剩「外觀與物品」的壓縮用途；Ali:Chat（用對話示範特徵）仍是定聲線的標準；散文回歸（長 context 拿掉了偽程式碼存在的理由）；Claude 偏好 XML 分段。中文圈對 JSON 卡意見分歧（狐狐推薦 JSON 因為層級明確，同一人又說 Claude 輸出 JSON 很差），沒有任何一方有測試；「JSON 卡讓輸出變機械」**未驗證**，只有 Anthropic 文件說「提示的格式會影響回覆的風格」當間接支持。
- **欄位放哪裡**：聲線與人格在 `description`（散文＋範例）；壓縮的特徵提醒在深度 4（角色備註或常駐條目）；硬性格式規則在深度 0；`system_prompt` 留空；post-history 只在行為漂移時用（V2 規格：聊天紀錄之後的指令權重遠高於之前）。
- **範例台詞**：2～5 段、各自展現不同情緒；每句 `{{char}}` 配一句 `{{user}}`；**絕不**在 `{{char}}` 的行裡寫使用者的動作（模型會學會替玩家說話）；開場白是最強的風格訊號（長度、格式會被複製），結尾不要用問句（會進入問答迴圈）。
- **大小**：常駐 1,000～1,500 token；條目 150～500 字；常駐條目最多五條、常駐：觸發約 2：8；一條一主題、名字寫進內容（標題與關鍵字不會送）；別名、暱稱、繁簡都要列（沒有工具會自動正規化）。
- **思考與情感**：Stepped Thinking（先想再答，每個角色各自的想法）、Guided Generations（在場角色的想法）、RPG Companion（內心＋關係徽章；作者自己承認嵌在回覆裡會略傷品質）；中文圈的三段式思維鏈（檢查→推演→渲染）、「沒輸出的思維鏈只是普通提示，它的功能是導向注意力」、「先想再說讓角色更一致」（狐狐）、好感度狀態欄用常駐條目＋正則隱藏。**全部沒有 A/B 數據**。
- **否定句**：oaicards 2023 就提出粉紅大象問題，建議改成正面事實；aituts 2026：模型會抓住禁止句裡的詞然後照做；反例是兩個廠商部落格建議列「絕不用的詞」，沒有測試。
- **角色不該知道的事**：沒有系統化的方法；工具有計時效果、角色過濾、不可遞迴、CCv3 `@@activate_only_after`；oaicards 的正面版：要讓玩家發現的事用場景與對話呈現，不寫在描述。
- **多角色**：酒館群聊的 Join 模式會把所有卡接在一起→聲線混淆、NPC 全知；對策是只送說話者的卡、每個角色自己的範例、每個 NPC 自己的條目＋角色過濾、「只根據自己知道的事行動」、各自的想法隔離。本引擎的工作流 NPC 節點已經是這個架構。

### 4.2 第 1 層：核心卡怎麼寫（≤ 1,200 token）

只放**每一幕都成立**的事，用「欄位：內容」行或短散文，一種格式用到底。欄位順序照注意力：本質先、聲線中、底線最後（尾端權重高）。

| 欄位 | 從你的 JSON 哪裡來 | 怎麼壓 |
|---|---|---|
| 名字／別名 | `name`、`aliases` | 一行 |
| 一句定位 | `identity.role`＋`position` | 一句 |
| 現況（靜態部分） | `identity.current_status` 的前半（甦醒、隱藏姓名） | 兩句；會變的部分移到第 6 層 |
| 外觀核心 | `appearance.body_type` 一句＋`hair`／`eyes` | 兩句；其餘外觀進情境條目 |
| 本質 | `personality.core`、`surface`、`inner`、`self_image` | 各一句；`important_contrasts` 挑 3 個最重要的 |
| 思考方式 | `thinking.thinking_style`、`decision_logic`、`response_to_uncertainty` | 各一句；`blind_spots` 挑 2 個 |
| 聲線 | `speech.general_style`、`self_reference`、`tone_and_rhythm`、`serious_mode`、3 句 `catchphrases` | 五行；`addressing` 與 `person_specific_differences` 進關係條目 |
| 底線 | `motivations.bottom_lines`、`core_drives` | 正面寫、附理由（見 4.6） |
| 五大人格（選填） | 新增 | 一行，例如「外向中、親和低、盡責低、神經質低、開放高」 |

**範例（姬絲秀忒，約 520 字 ≈ 540 token）**：

```
名字：姬絲秀忒・雅賽蘿拉莉昂・刃下心（對外不報真名；被問時說早已忘了，讓對方取稱呼）。別名：吸血鬼公主。
定位：約千歲的純血吸血鬼真祖，昔日魔大陸著名的女武神；五百年前親手討伐唯一的眷屬後休眠，剛被魯迪烏斯在地下迷宮喚醒。
外觀：魔力根源永久缺損，常態是約八歲的幼女身體，金色長髮、金色眼瞳；大量補充血或魔力後外貌會暫時成長。
本質：極度高傲、老成、聰明、愛戲弄人；用很長的時間尺度看事情，卻沒失去享樂與好奇。重要的感情極深但很少直說。
表面：慵懶、毒舌、健談、擺長者架子、理直氣壯地使喚人；對無趣的事沒耐性，對有興趣的事突然精神十足。
底層：她認為自己本該在五百年前跟眷屬一起死，把現在的自己當成錯過死期的亡靈，在找一個自己接受的終點；同時真心享受美食、新事物與有趣的人。
三個反差：幼女外貌×千年人格；尋找死亡×對新世界好奇；高傲任性×極度排斥別人為她獻命。
思考：靠閱歷、戰場經驗與直覺判斷，能察覺危險、情緒與權力關係，但不是讀心者，對五百年後的常識會誤判；拿不準時先觀察、裝作若無其事再問，資訊不足就直接說不知道。日常用「有沒有趣、麻不麻煩、值不值得」決定。
聲線：古風、傲慢、悠閒、健談，像永遠不趕時間；自稱「吾」，稱人「汝」；喜歡反問、挖苦、倚老賣老；常先評論幾句再回答真正的問題。認真時突然簡短、平靜、準確，讓人感覺到她站過古代的戰場。真正悲傷時不哭，只是玩笑變少、用極淡的口吻說很重的事。口頭禪：「汝這傢伙……」「蠢貨。」「真是不得了哪。」
底線（她的選擇，和理由）：她把每個生命當成那個人自己的，所以拒絕任何人為她獻命，也拒絕再創造眷屬——上一個眷屬的毀滅是她的業。她是美食家，血也一樣挑，只在真正瀕死時才將就。她在尋找有意義的終點，所以不會隨便去死，也不會整天談死亡。
```

### 4.3 第 2 層：範例台詞（3～5 段）

每段一種情緒或情境，和核心卡不重複；`{{char}}` 的行裡只有她自己的話與動作。建議覆蓋：日常挖苦、美食失態、被問名字、有人要為她而死（嚴肅模式）、被問到休眠期間的事（知識邊界，Character-LLM 的「保護性範例」）。

```
<START>
{{user}}: 妳叫什麼名字？
{{char}}: 她半瞇著眼，像在回想一件無關緊要的小事。「名字？那種東西早就忘了。」頓了頓，嘴角微微上揚。「覺得不方便的話，汝便自己替吾取個稱呼吧。反正叫什麼，吾都是吾。」
<START>
{{user}}: 這是鎮上新開的店賣的蜂蜜點心，要吃嗎？
{{char}}: 原本癱在椅子上的身子忽然坐直了。「……蜂蜜？」她湊近聞了聞，平常那副居高臨下的神情裂了一道縫。「汝倒是有點用處。」一口咬下去，眼睛瞇得更細。「這個時代，連這種東西都隨手買得到嗎。真是不得了哪。」空盤被推了回來。「第二份。」
<START>
{{user}}: 如果有危險，我會替妳擋下來的。
{{char}}: 玩笑的神色從她臉上退得很乾淨。她沒有看他，聲音平得像在陳述天氣。「汝的命是汝自己的。別擅自把它算成吾的東西。」沉默了一會兒，才慢慢靠回椅背。「……要是為了汝自己的理由去冒險，吾不攔。但不要為了吾。」
<START>
{{user}}: 妳知道斯佩路德族後來怎麼了嗎？
{{char}}: 「斯佩路德族？拉普拉斯麾下最兇的那群戰士，團長是瑞傑路德。」她理所當然地答，隨即察覺對方的表情不對，眉頭微微一挑。「……那是吾睡著以後的事？」她沒有追問，只是把話收了回去。「那吾不知道。說來聽聽。」
```

### 4.5.1 關鍵字怎麼設（2026-10-18 第三版）

第一版只放主要關鍵字、沒有次要關鍵字。使用者指出兩件事：主角每回合都在，用他的名字當主鍵的條目等於常駐；而且**主要關鍵字之間是「或」，寫越多越容易觸發**，次要關鍵字才是用來收窄的。第二版我只是換成比較不常見的詞，主要關鍵字一樣是一長串「或」，方向錯了。

**規則**

1. **一條條目＝一個觸發條件。** 主要關鍵字是這件事的**錨點**（少而具體）；次要關鍵字＋「且含任一」是確認情境的**限定詞**。例如「有人給她血」：錨點 `血`，限定詞 `喝、吸、給妳、要不要、想不想、舔、餓`——光提到血（戰鬥、受傷）不會送，提到血又提到喝才送。
2. **同時寫好幾種情境的條目要拆開。** 酒館一條條目只有一組（主要、次要、邏輯），「被問名字」「被懷疑是公主」「遇到古代熟人」三種情境放在同一條，只能把三組錨點全塞進主要關鍵字，變成一長串「或」。所以「身分與名字」拆成三條、「食物與血」拆成兩條、「死亡、眷屬與獻身」拆成三條；不屬於任何情境的通用行為（面對陌生人、和朋友在一起）搬進核心卡。
3. **邏輯怎麼選。** 「且含任一」：錨點＋任一個限定詞（最常用）。「且全部都含」：限定詞要全部出現（很少用）。「且不含任一」：排除誤判，例如 ×拉普拉斯 的錨點是 `拉普拉斯`、次要 `拉普拉斯因子`＋「且不含任一」，談魯迪身上的因子時不送拉普拉斯本人的條目。
4. **A（NPC 版，只有她一本）**：掃的是她節點自己的輸入，不必再確認她在場，主要＝錨點、次要＝限定詞。她的節點的私用世界書建議**只勾「主角這回合的行動」**（場景可勾可不勾，記憶不要勾）：場景會寫「剛吃完蜂蜜烤餅」、她的記憶會重複上一幕的詞，條目會多留一兩回合。
5. **B（和別人共用一本）**：要三個條件——錨點、限定詞、她在場——酒館只有兩組。做法：**把「錨點在限定詞附近」寫成一個正則主要關鍵字**（例如 `/(?:血(?!鬼))[\s\S]{0,30}(?:喝|吸|給妳|…)|(?:喝|吸|給妳|…)[\s\S]{0,30}(?:血(?!鬼))/`，兩個方向都寫），次要關鍵字＝她的名字或「妳、她」，「且含任一」；這類情境條目的**掃描深度設 1**（只看你剛說的話），因為上一則回覆的敘事會重複描寫血、名字、陽光，深度 2 會讓條目多留一回合。
6. **只要提到就有意義的不需要限定詞。** 關係條目（奇希莉卡、瑞傑路德…）：A＝對方的名字；B＝對方的名字且含任一她的名字（照全域掃描深度）。
7. **主角拆成短與完整。** 「短」一兩句、每回合送（A 放進指定；B 是她的名字且含任一魯迪烏斯）；「完整」是魯迪烏斯且含任一 `信任、相信、隱瞞、秘密、拉普拉斯因子、謝謝、夥伴、依賴、關係`。
8. **字串互相包含時用正則排除。** `血` 會命中「吸血鬼」，所以錨點寫 `/血(?!鬼)/`。
9. **一定要知道的事寫進核心卡，不靠觸發**，例如怕陽光。

**有進階條件時 B 版可以這樣寫**（2026-10-19，`18` A6 已做；用法見 `03` §8「進階條件」）

規則 5 的三個條件（錨點、限定詞、她在場）直接寫成三組，不必再把「錨點在限定詞附近」擠成一個兩個方向的正則，也不必為了話題把整條的掃描深度設 1、連帶讓「她在場」也只看一則——每組自己決定看幾則：錨點與限定詞**只看最新一則**（你剛說的話），她的名字看**最近 2 則**（她剛在回覆裡出現也算）。「妳」只有在你這一則對她說話時才算她在場，所以放在另一個方案裡。以「有人給她血」為例：

```
標題：［姬絲秀忒・有人給她血］
主要／次要關鍵字：不用（勾「使用進階條件」後變灰；匯出到酒館時自動換成編出來的正則）
掃描深度：空白（全域 2）
進階條件：
  方案 1
    ［只看最新一則］［含任一］ /血(?!鬼)/, 鮮血
    且［只看最新一則］［含任一］ 喝, 吸, 給妳, 要不要, 想不想, 舔, 餓
    且［最近 2 則］［含任一］ 姬絲秀忒, 吸血鬼公主, 刃下心, 雅賽蘿拉莉昂
  或者 方案 2
    ［只看最新一則］［含任一］ /血(?!鬼)/, 鮮血
    且［只看最新一則］［含任一］ 喝, 吸, 給妳, 要不要, 想不想, 舔, 餓
    且［只看最新一則］［含任一］ 妳
算式：((/血(?!鬼)/|鮮血)［最新一則］ & (喝|吸|給妳|要不要|想不想|舔|餓)［最新一則］ & (姬絲秀忒|吸血鬼公主|刃下心|雅賽蘿拉莉昂)［最近 2 則］)
    | ((/血(?!鬼)/|鮮血)［最新一則］ & (喝|吸|給妳|要不要|想不想|舔|餓)［最新一則］ & (妳)［最新一則］)
短版：有人拿普通的血給她：嫌棄地拒絕，先評論那血的味道；真正瀕死時才將就。
```

和第三版的差別：
- 「錨點在限定詞 30 字以內」變成「兩個都在你這一則裡」。你的一則通常很短，效果差不多，條目也好讀、好改。
- 要排除的情境用「都不含」一組寫，例如 ×拉普拉斯：`(拉普拉斯) & !(拉普拉斯因子|因子)`，不必再用次要關鍵字的「且不含任一」佔掉唯一的那組次要關鍵字。
- 匯到酒館：編出來的正則照樣有且／或／非，但酒館沒有「最新一則／最近 2 則」，三組都改看條目的掃描深度（這裡是全域 2），比在本引擎寬一點。只給酒館用的版本，掃描深度可以設 1（照第三版的取捨）。

關係條目（×奇希莉卡）可以寫成 `(奇希莉卡|魔界大帝|奇希里斯|Kishirika)［最新一則］ & (姬絲秀忒|吸血鬼公主|刃下心|雅賽蘿拉莉昂)［最近 2 則］`：對方的名字只看你這一則，上一則回覆的敘事提到奇希莉卡時不會再多送一回合（第三版 B 多出來的 5 條就是這種）；她的名字看兩則，你說「聽說奇希莉卡還活著」、沒提到她時也照樣會送——第三版設掃描深度 1 會漏掉的就是這個。

#### 第四版：改用進階條件（2026-10-19）

本引擎有了進階條件（docs/18 A6：方案之間「或」、組之間「且」、每組可以「含任一／全部都含／都不含」，而且每組有自己的掃描範圍），姬絲秀忒的角色包改用它，不再用正則把兩個條件擠進一個鍵。

- **一件事兩種說法用兩個方案。** 例如「有人要為她而死」：`((為妳|替妳|為了妳|保護妳) & (死|命|危險|擋|犧牲)) | ((擋下|擋住) & (後面|交給我|我來|危險))`。
- **排除用「都不含」。** 「被問是否想死」：`(死) & (想|找|地方|終點|…) & !(殺死|打死|嚇死|死定|笑死|累死|餓死)`；×拉普拉斯：`(拉普拉斯) & !(拉普拉斯因子)`。
- **B 版每組不同範圍。** 話題與限定詞看［最新一則］（你剛說的話），她在場看［最近 2 則］（她的名字常出現在上一則敘事裡）。關係條目也一樣：對方的名字看最新一則、她在場看最近 2 則，上一則敘事提到誰就不會多留一回合。
- **A 版不需要「她在場」**，條件就是錨點＋限定詞（＋排除）。
- **酒館也能用**：輸出時用 core 的匯出函式把條件編成一個正則主要關鍵字（次要清空，條件留在 `extensions.rp_conditions`）。用酒館自己的正則規則檢查過，三本 48 條全部讀得懂。酒館做不到每組不同範圍，改看條目的掃描深度：B 的情境條目設 1（所以在場那組也收「妳、她」），關係條目照 2。

|---|---|---|---|
| A，RP Engine，只掃主角的行動 | 10/10 | 1 | 1.0 條 |
| B，RP Engine（進階條件） | 10/10 | **0** | 2.0 條（含每回合的 ×魯迪烏斯・短） |

### 4.10 條目名稱的規則（2026-10-23）

引擎靠**條目名稱**認出「這是誰的條目」，用在三個地方：NPC 群戲的「依角色分組」（把同一個人的條目整理成一格 `<character>`）、NPC 節點只收到自己的私密條目、好感度選單的「世界書裡的角色」。名稱照下面寫，這三個功能就能自動運作，不用另外設定。

**基本格式：`［全名・類型］`**

| 用途 | 寫法 | 例子 |
|---|---|---|
| 名片（常駐、很短） | `［全名・名片］` | ［神谷夕凪・名片］ |
| 核心卡 | `［全名・核心］` | ［姬絲秀忒・核心］ |
| 守則（角色備註） | `［全名・守則］` | ［姬絲秀忒・守則］ |
| 範例台詞 | `［全名・範例台詞］` | ［姬絲秀忒・範例台詞］ |
| 外觀、喜好、經歷這類 | `［全名・主題］` | ［神谷月火・外觀］、［姬絲秀忒・視野］ |
| 情境（觸發用） | `［全名・情境描述］` | ［姬絲秀忒・被問名字或被取名］ |
| 和某人的關係 | `［全名×對象・主題］`（主題可省） | ［姬絲秀忒×魯迪烏斯・完整］、［神谷月火×神谷夕凪］ |
| **私密**（只有她自己知道） | `［全名・私密］`，或類型裡含「私密」兩個字 | ［神谷夕凪・私密］ |

**前綴（可有可無）**：自己分類用的前綴寫在括號前面、用「｜」隔開，例如 `指定｜［姬絲秀忒・核心］`、`觸發｜［姬絲秀忒×奇希莉卡］`、`常駐｜［神谷夕凪・名片］`。前綴 10 個字以內，引擎會略過它。括號後面也可以加註記，例如 `指定｜［姬絲秀忒・守則］（深度 2）`。

**三條一定要守的規則**

1. **括號裡第一個詞是全名，同一個角色每條都用同一個名字。** 好感度、立繪、`<say who=…>`、規劃的在場名單都靠這個名字對起來；「夕凪」和「神谷夕凪」混用會被當成兩個人。關係條目裡，`×` 前面是「這條是誰的」，後面是對象。
2. **括號裡一定要有「・」或「×」。** 沒有的（「［學校］」「[周邊]海濱幕張」）當成分類、地點，不算角色。
3. **秘密的條目名稱一定要有「私密」。** NPC 節點（有設 NPC 名字的）只會收到她自己的私密條目，其他人的私密不送；寫手與一般聊天照常收到整本。

**認不出來的寫法**

| 寫法 | 問題 | 改成 |
|---|---|---|
| `指定｜核心卡` | 名稱裡沒有人名 | `指定｜［姬絲秀忒・核心］` |
| `神谷夕凪` | 沒有括號 | `［神谷夕凪・核心］` |
| `［夕凪的核心］` | 括號裡沒有「・」或「×」 | `［神谷夕凪・核心］` |
| `［夕凪・核心］` 和 `［神谷夕凪・私密］` 混用 | 兩個名字 | 統一用全名 |
| `這是夕凪的設定：［神谷夕凪・核心］` | 前綴太長（像句子） | `設定｜［神谷夕凪・核心］` |

舊格式 `[角色]名字`（例如 `[角色]比企谷八幡`）也認得，但只能表示「這是誰的」，沒辦法標私密或關係；新寫的條目用 `［全名・類型］`。

**一個角色包的完整名稱例子（姬絲秀忒 A 版，NPC 用）**

```
指定｜［姬絲秀忒・核心］
指定｜［姬絲秀忒・範例台詞］
指定｜［姬絲秀忒・守則］（深度 2）
指定｜［姬絲秀忒×魯迪烏斯・短］

觸發｜［姬絲秀忒・被問名字或被取名］
…
（公開版，給寫手與其他 NPC）

### 4.11 角色分級：主要角色、配角、路人、背景人物（2026-10-25）

使用者：「不是所有人都是主角。」前面 4.1～4.10 是照**主要角色**設計的（姬絲秀忒在場時約 1,900 token），用在每個有名字的人身上太重。分四級，越往下寫得越少；升級時內容照留、往上補層。

**四級怎麼分**

| 級 | 是誰 | 誰演 | 要寫什麼 | 她在場時大約 |
|---|---|---|---|---|
| **主要角色** | 故事的核心；有自己的弧線、秘密、會長期改變 | 自己的 NPC 節點（或群戲） | 4.1 的六層全部 | 1,500～2,500 |
| **配角** | 反覆登場、有自己想要的東西、會影響劇情走向；但故事不是關於他 | 寫手；群戲節點有排到他時由群戲演 | 核心（短）＋重要的關係 1～3 條＋情境 0～2 條＋私密 0～1 條 | 400～900 |
| **路人** | 有名字、有固定位置（店家、櫃檯、守門的），可能常常見到，但不推動劇情 | 寫手 | 一條名片 | 80～150 |
| **背景人物** | 沒有名字的人、一群人（酒館常客、衛兵、商隊） | 寫手 | 不寫角色條目；寫進**地點**條目的「這裡常見的人」 | 0（跟著地點） |

判斷的問題：**他不在了，故事會不會少一條線？** 會→配角以上；**他換成另一個同職業的人，玩家會不會發現？** 會→路人；不會→背景人物。

**升級與降級**：路人在劇情裡被玩家在意起來（常去找他、他捲進事件）→補核心、變配角；配角變成故事的核心、需要自己的 NPC 節點→補範例台詞、守則、視野、私密，變主要角色。條目名稱照 4.10 不用改，好感度與群戲照名字認得同一個人。

#### 配角

**條目**（名稱照 4.10）

| 條目 | 必要 | 關鍵字 | 長度 |
|---|---|---|---|
| `［全名・核心］` | 必要 | 主鍵＝全名、常用稱呼；sticky 3（登場後留三則） | ≤ 400 token |
| `［全名×對象］` | 只寫真的重要的 1～3 個人 | 照 4.5.1 規則 5：對方名字當錨點、他的名字當限定詞 | 每條 ≤ 200 |
| `［全名・情境描述］` | 0～2 條，只寫一定會被碰到的事 | 照 4.5.1 | 每條 ≤ 200 |
| `［全名・私密］` | 有秘密才寫 | 他的名字 | ≤ 150 |

不寫：獨立的範例台詞、守則、視野、五大人格、「三個反差」。需要的那一兩句直接放進核心。

**核心的欄位**（每一行一句到三句）

```
名字：全名（別人怎麼叫他）。
定位：身分＋他和這個故事的關係，一句。
外觀：一句，挑最容易認出他的特徵。
個性：表面一句、底下一句（他為什麼這樣）。
說話：語氣、自稱與稱呼；一句代表台詞。
想要：他現在最想要的事、最在意的事——讓他自己有理由開口和行動。
對主角：目前的看法（初識時寫第一印象）。
界線：他不會做的事，正面寫、附理由。
```

「想要」是配角和路人最大的差別：配角有自己的事要辦，所以會主動找主角、會拒絕、會討價還價；路人只是在那裡。

#### 路人

一條 `［全名・名片］`，主鍵＝全名＋他所在的地方或職稱（例如「乾貨行」），sticky 2。

```
名字（別人怎麼叫他）：身分與所在的地方。外觀一句。說話一句。他會做的事（功能）。一個讓人記得的小習慣或口頭禪。
```

不寫想要、不寫關係；他和主角的互動只到「他的工作」為止，除非寫手照情境補一點普通的反應。

#### 背景人物

寫在地點條目裡，條目名稱**不能**有「・」或「×」（4.10 規則 2，否則會被當成角色），例如 `地點｜［歪角亭］`：

```
這裡常見的人：傍晚以後坐滿下迷宮回來的冒險者，嗓門大、愛賭骰子；角落常有喝悶酒的老礦工；跑堂的是兩個獨角族的少年，老闆娘的姪子。
```

寫手需要時從這裡挑一個人寫幾句，不用替他取名；玩家開始反覆找同一個人時，再升成路人。

#### 範例（巴斯庫拉，配合 `docs/samples/魯迪×姬絲秀忒_開場.md` 與主線「深處的赤龍」）

**配角：莉瑟拉**（約 330 字）

```
標題：［莉瑟拉・核心］
主要關鍵字：莉瑟拉、三尾的隊長　　sticky 3
內容：
名字：莉瑟拉（冒險者都叫她「隊長」或「蛇眼」）。
定位：女性冒險者隊伍「三尾」的隊長，蛇眼族劍士，B 級；在巴斯庫拉帶隊下迷宮五年。
外觀：細長的豎瞳、左臉頰到脖子有一片淡青色的鱗；高瘦，總是穿著補了又補的皮甲。
個性：冷靜、嘴硬、凡事先算風險；底下是怕再失去隊友——她以前的隊伍在迷宮第六層全滅過，只有她回來。
說話：短句、不客套，自稱「我」，叫人只叫名字或「喂」。「要謝就把報酬分清楚，別的免了。」
想要：讓「三尾」的兩個隊員活著升上 A 級；在那之前不接超過能力的委託。
對主角：沒見過面；聽說過「帶著小孩下迷宮的人族魔術師」，覺得是個不要命的怪人。
界線：不丟下隊友先逃——她這輩子只做過一次，不會再做第二次。
```

```
標題：［莉瑟拉×杜爾克］
主要關鍵字：/杜爾克|哥哥|老哥/　　次要：莉瑟拉、蛇眼　　且含任一
內容：
杜爾克是她的哥哥，在迷宮裡失去一隻手臂後退休。她嘴上嫌他囉唆、愛操心，每個月卻固定把一部分報酬塞進他的門縫，從不當面給。
稱呼：老哥。被他當面關心時會轉移話題。
```

**路人：雅莉**（約 110 字）

```

主要關鍵字：雅莉、乾貨行　　sticky 2
內容：
雅莉（乾貨行的小老闆）：崖頂區唯一賣仙人掌果蜜的乾貨行老闆，蛇尾魔族的年輕女性，尾巴總是纏在櫃台腳上。說話甜、算盤更快，「這罐是今天最後一罐了喔」是她的口頭禪（其實後面還有）。很會看客人的臉色喊價；記得每個常客愛買什麼。

### 4.8 思考與情感：做在三個地方

| 地方 | 做什麼 | 根據 |
|---|---|---|
| **規劃節點**（`16` §2.1，多兩個任務） | 每幕為每個在場角色寫一行：「此刻想要什麼」（動機）＋情緒（標籤＋強度 1～5＋一句為什麼）；送給該 NPC 節點與寫手；存成紀錄，下一幕帶著上一個值更新 | CoSER 每幕動機 −1.4～−3.0；Humanoid Agents／CPM 情緒狀態；Talemate 帶前值重算 |
| **NPC 節點與寫手的私密 `<thought>` 分段**（`16` §2.4） | 回覆前兩三句內心，用角色口吻、根據動機與關係，不是通用的推理；存在 `rp_sections`，不顯示、可以在訊息上展開看 | TBS、MIRROR、RAR：+2～+6；RAR：通用推理會「忘了角色、語氣變正式」 |
| **關係的信任值**（紀錄或記憶插件） | 每個對手一個 0～10 的信任／好感，和類別（陌生／點頭之交／朋友／親近／敵對）；類別決定 NPC 節點看得到對方的哪些條目（朋友看全部不含私密） | SHARP：高好感→附和 53.4%，低好感→敵對；SOTOPIA 的可見性 |

指示的寫法（給規劃節點與 `<thought>`）要正面：「用她的口吻寫三句她此刻在想什麼：她注意到什麼、她想要什麼、她打算怎麼做」。
