## 1. 玩家決定走向：現在有什麼、還缺什麼

**現在有的（每個聊天各自，在 ☰ →「劇情推演」視窗，不在插件設定裡）**

| 控制 | 作用 |
|---|---|
| 走向（預設／喜劇／嚴肅／危險／自訂一句話） | 推演時的整體風格；改了 20 秒後重跑最近一次推演 |
| 強度（慢熱／平穩／積極／狂野） | 世界有多活躍：時鐘走多快、事情多不多 |
| 預期的方向（一段文字，在視窗下方「故事設定（主線）與預期的方向」） | 「你希望接下來大概往哪走」，推演當作偏好參考 |
| 修改推薦的發展、線、伏筆 | 直接改推演的結果 |

插件設定（🧩）只有「預設的強度」，所以從設定那頁看不到這些。

**可能缺的**：玩家「挑一條」的手感。建議的做法（都維持「只推薦、不命令」）：

- **A. 推薦旁邊加「想往這邊」**：在視窗裡點一個推薦，它就變成下一次推演的「預期的方向」，推演會讓世界往那邊長，但寫手照樣只拿到參考。
- **B. 視窗上方放「預期的方向」快速欄**：不用捲到下面；也可以在聊天畫面加一個小按鈕直接打開。
- **C. 主線開著時，「預期的方向」可以選「照主線走／暫時離開主線（日常、支線）」**：離開時推演不推主線的錨點，只讓時鐘照走。

這三個不互斥，要你決定要哪幾個。

## 2. 主線模板（JSON）

### 2.1 一份主線長什麼樣子

```jsonc
{
  "type": "rp-mainline",        // 固定，用來辨認檔案
  "version": 1,
  "title": "深處的赤龍",
  "teaser": "給玩家看的一句話（不能劇透）",
  "pitch": "概要：給人看的一兩句話，不送給推演（不要劇透，真相放 truths；2026-10-25 改）",
  "length": "約 100 回合",       // 只是參考
  "tone": "整體調性",
  "principles": ["給推演與寫手的原則", "…"],
  "cast": [ { "name": "人物", "who": "是誰", "role": "在主線裡的用途" } ],
  "truths": [                    // 真相：只給推演，分段解鎖
    { "id": "dragon", "from": 3, "text": "從第 3 段起推演才知道的事" }
  ],
  "clocks": [                    // 會自己往前走的事；從某一段才開始
    { "id": "nest", "name": "龍巢", "size": 6, "from": 3, "tick": "每一格代表什麼", "full": "填滿時發生什麼" }
  ],
  "segments": [                  // 依序的段落
    {
      "id": "s1", "title": "湧出", "turns": "1～20", "drive": "slow",
      "world": "這一段世界在發生什麼（玩家不介入也會走）",
      "anchors": [ { "id": "night-raid", "text": "一定會發生的事（時機跟著玩家，不強制）" } ],
      "options": ["玩家可以做的事（給推演當參考）"],
      "exit": "進入下一段的條件（自然語言，推演判斷）"
    }
  ],
  "outcomes": [                  // 玩家的選擇要被後面讀到的
    { "id": "egg-fate", "question": "蛋最後怎麼處理了？", "from": "s4", "readFrom": "s5" }   // from：從哪一段起推演開始留意（選填）
  ]
}
```

欄位都是自然語言，只有 `id`、`from`、`size`、`drive`、`readFrom` 是給程式用的（`from`、`readFrom` 可以寫段的 `id` 或第幾段的數字）。沒有用到的欄位可以省略（最小的主線只要 `title` 和 `segments`）。

### 2.2 為什麼這樣分（對應主線文件第 6 節的需求）

| 需求 | 欄位 |
|---|---|
| 只給推演目前這一段 | 推演時只送 `principles`、`cast`、`from` ≤ 目前段的 `truths`、**目前這一段**的 `world`／`anchors`／`options`／`exit`；後面的段完全不送。`pitch`（概要）不送：原本每段都送整條的概要，Gemini 實測第 1 段就把結局寫進真相欄位（2026-10-25 拿掉） |
| 錨點與關卡 | `anchors`（推演回報哪些已發生）＋`exit`（推演判斷到了沒；也能手動標） |
| 錨點可以等 | 錨點沒有時鐘，不會因為回合到了就發生；推演只在時機自然時把它放進世界 |
| 時鐘從某一段才開始 | `clocks[].from`：到那一段才變成一條線（接上現在的「線＋時鐘」） |
| 玩家的選擇影響後面 | `outcomes`：該段結束時推演寫下答案，`readFrom` 之後的段都讀得到 |
| 每段不同強度 | `segments[].drive`（沒寫就用聊天選的） |
| 線索一次一個 | `truths[].from` 控制推演什麼時候才知道 |

### 2.3 執行時的狀態（不寫在模板裡）

主線匯入到聊天後，進度存在聊天上：目前第幾段、每個錨點有沒有發生（第幾回合）、`outcomes` 的答案、每段開始的回合。時鐘照現在的做法存在推演結果的線裡（swipe／倒退自然復原）。**模板本身不改**，所以同一份模板可以給好幾個聊天用。

## 3. 怎麼匯入

| 方式 | 適合誰 | 做法 |
|---|---|---|
| **A. 匯入 JSON 檔** | 已經照格式寫好、或拿別人分享的 | ☰ →「劇情推演」→「主線」→ 匯入 `.json`；檢查格式，有錯就指出是哪一段 |
| **B. 貼文字，讓 AI 轉成 JSON** | 手上是小說大綱、像 `魯迪×姬絲秀忒_主線.md` 這種文件 | 貼上 Markdown／純文字 → 用推演的連線呼叫一次 AI 轉成上面的格式 → 先給你看、可以改，再存 |
| **C. 從世界書條目匯入** | 主線已經寫成世界書條目的人（docs/12 原本的想法） | 勾選條目 → 同 B，交給 AI 轉 |
| **D. 從模板開始寫** | 想自己設計 | 內建幾個空白骨架（例如「五段冒險」「三幕日常」「懸疑調查」），在視窗裡逐欄填 |
| 匯出 | 分享、備份 | 把聊天用的主線存成 `.json`（不含進度） |

建議先做 **A＋匯出**（最簡單、格式先穩定），再做 **B**（你的主線大多是文件形式，B 最省事），C、D 之後。

**存在哪裡**（要你決定）：
- 只存在聊天裡（每個聊天一份，最簡單；分享靠匯出）；或
- 另外有一個「主線庫」（像預設一樣存在 `data/` 裡，開新聊天時選一份；要多一點伺服器的工作）。

## 4. 決定（2026-10-24）

使用者：「我感覺都可以做，但先做A就好。也不錯，加一個主線庫巴。也行，妳之後給個範本JSON，我之後要給寫劇情的AI參考」

1. **玩家決定走向**：A、B、C 都要，**先做 A**。✅ A 已完成：推薦旁邊的「想往這邊」（docs/04 第 46 項）。B、C 之後。
2. **匯入**：先做 A（匯入 JSON）＋匯出，再做 B（貼文字讓 AI 轉）；C、D 之後。
3. **要有主線庫**：主線存在 `data/` 的主線庫（像預設一樣），開新聊天或在視窗裡選一份；聊天上只存進度（第 2.3 節）。docs/04 第 47 項。
4. **格式可以**：照第 2 節。給寫劇情的 AI 參考的檔案：
   - 空白骨架：`docs/samples/主線模板.json`
   - 寫作說明（可以整段貼給 AI）：`docs/samples/主線模板_寫作說明.md`
   - 完整範例：`docs/samples/主線_深處的赤龍.json`

## 5. 做好的樣子（2026-10-24）

- **主線庫**存在插件設定（`settings.mainlines`）；☰ →「劇情推演」→ 上方「主線」：匯入檔案、貼上 JSON（格式有錯指出是哪一段、哪一欄）、匯出、刪除。
- **聊天用主線**：選一份、從第幾段開始 → 複製一份到聊天上（`chat_metadata.rp_plot.main`）；開關；不用。
- **進度**存在每一次推演的結果上（`PlotResult.main`：第幾段、這一段從第幾回合開始、發生過的錨點、記下的結果、已經放進世界的時鐘、這次有沒有進段），swipe／倒退自然復原。視窗可以手動打勾錨點、改結果、換段。
- **推演讀**：概要、調性、原則、人物、`from` ≤ 目前段的真相、目前這一段的世界／錨點（標已發生／還沒）／玩家可能做的事／進入下一段的條件、已有答案而且到了 `readFrom` 的結果、還沒有答案而且到了 `from` 的結果。這一段的 `drive` 在聊天沒有自己選強度時用。
- **推演回報** `<anchor id>`、`<outcome id>`、`<advance>`；進段後下一回合自動提早推演一次（原因「主線新的一段」）；最後一段的條件達成就結束。
- **主線的時鐘**到了 `from` 那一段才變成一條線（id `m-<時鐘 id>`），只放一次。
- **寫手不收主線本身**，只收推演放進世界的線（表面）與推薦。
- 程式：`progression/mainline.ts`（讀入與檢查、進度、給推演的區塊、解析回報）、`progression/ui/MainlinePanel.vue`。
- 「預期的方向」B（視窗上方快速欄）、C（照主線走／暫時離開主線）與匯入 B（貼文字讓 AI 轉）還沒做。
- 實測（`reports/主線與提早推演實測報告.md`）：主線開著推演 3／3、進段 3／3、不該進段 3／3、進段後提早推演 3／3，寫手看得到的內容沒有後面段落的真相。發現「進入下一段的條件」要寫成只有一種讀法（寫作說明已補）。
